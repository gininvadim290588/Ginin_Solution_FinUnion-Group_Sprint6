rectangle "Регулятор" as Regulator <<external>>
rectangle "Клиенты /\nмобильные и веб-каналы" as Channels <<external>>

Channels --> OPS : операции, обращения
OPS --> ESB : синхронные запросы\n(проверка клиента, баланс)
OPS --> CDC : изменения записей\n(row-level changes)
CDC --> Kafka : события изменений\n(CDC-топики)
OPS --> Kafka : бизнес-события\n(транзакция, платёж, кейс)

ESB --> MDM : Read/Write клиентских\nи справочных данных
MDM --> ESB : golden record\n(client_id, продукт, тариф)
ESB --> OPS : публикация эталонных\nданных

Kafka --> Lakehouse : streaming запись\n(Iceberg-таблицы)
Kafka --> Graph : обогащение графа\nсвязей в реальном времени
Kafka --> Search : индексация обращений

Airflow --> DWH : batch-загрузка\nи трансформации (dbt)
OPS --> Airflow : выгрузки для DWH\n(регламентные, ночные)
Lakehouse --> Airflow : агрегация в DWH\n(витрины)
Airflow --> ObjStore : архивация\nзакрытых записей

DWH --> BI : регламентированные\nвитрины
Lakehouse --> BI : ad-hoc аналитика\n(через Trino)
DWH --> Regulator : регуляторная\nотчётность

MDM --> DataHub : метаданные\nи владельцы
DWH --> DataHub : lineage
Lakehouse --> DataHub : lineage
Airflow --> DataHub : lineage пайплайнов

note bottom of MDM
  Единственная система, где хранятся
  золотые записи Клиента и справочников
  (Продукт, Тариф, Отделение, Контрагент)
end note

note bottom of Lakehouse
  Iceberg-таблицы поверх объектного
  хранилища; Trino — движок для
  ad-hoc SQL и федеративных запросов
  DWH + Lakehouse
end note

@enduml
