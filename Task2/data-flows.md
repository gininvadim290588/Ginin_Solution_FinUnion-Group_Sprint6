# Потоки данных

Диаграмма: `diagrams/data-flow-diagram.puml` — DFD промежуточного состояния (3 месяца), показывающая
системы-источники, MDM, аналитический контур и внешних потребителей. Ниже — текстовое описание каждого
потока: источник, приёмник, сущности, действие, режим обмена и обоснование.

## Клиентские потоки (MDM Customer Hub)

| № | Источник | Приёмник | Сущности | Действие | Режим обмена | Обоснование |
|---|---|---|---|---|---|---|
| 1 | RB CRM | MDM Customer Hub | Клиент | Create / Update / Deduplicate | CDC (near real-time) | Построение золотой записи клиента и матчинг с FU-профилями сразу при изменении в RB CRM |
| 2 | FU CRM | MDM Customer Hub | Клиент | Create / Update | CDC (near real-time) | FU CRM — второй producer клиентских данных, участвует в том же матчинге |
| 3 | MDM Customer Hub | ФНС / ПФР / БИК ЦБ | Клиент | Validate | Синхронный (API-вызов) | Проверка ИНН/СНИЛС при онбординге, обязательна до публикации золотой записи |
| 4 | MDM Customer Hub | FU Core, RB Core, FU Loans, RB Loans, Contact Center | Клиент (golden client_id) | Read / Enrich | Batch (регламентный) на 3 мес., переход на CDC к 12 мес. | Распространение эталонного идентификатора клиента во все системы-потребители без прямого обращения к CRM-источникам |

## Комментарий по режимам обмена

- **CDC / streaming** используется там, где расхождение данных даже на несколько часов создаёт риск
  (клиент, антифрод, событийные данные) — это ключевое отличие целевого состояния от As-Is, где RetailBank
  использовал только point-to-point-интеграции без единого подхода.
- **Batch** сохраняется для регламентированной отчётности (DWH → BI/Регулятор) и для потоков, где нагрузка на
  OLTP должна быть исключена в рабочее время — прямое требование ограничения "аналитика не должна создавать
  нагрузку на операционные системы".
- **Sync API** применяется только для потока валидации (MDM → внешние реестры), так как результат нужен
  немедленно для принятия решения о публикации золотой записи.
