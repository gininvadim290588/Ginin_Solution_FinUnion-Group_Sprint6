# Логическая модель данных

## 1. Общая модель

Центральной сущностью модели является **Party / Клиент**.

Финансовые сущности связаны с клиентом через договоры, счета, карты и кредитные обязательства.

```text
Party
 |
 +-- Customer Profile
 |
 +-- Customer Segment
 |
 +-- Agreement
 |      |
 |      +-- Product
 |      +-- Tariff
 |      +-- Account
 |      |     |
 |      |     +-- Transaction
 |      |     +-- Payment
 |      +-- Card
 |      +-- Loan
 |
 +-- Customer Case
 +-- Document
 +-- Relationship
 +-- Counterparty
```

## 3. Ключевые бизнес-правила

### Клиент

Один клиент может иметь:

- несколько счетов;
- несколько карт;
- несколько договоров;
- несколько кредитов;
- несколько обращений;
- несколько документов;
- множество связей с другими клиентами и организациями.

### Счёт

Счёт принадлежит клиенту и может быть связан с договором и продуктом.

По счёту проводится множество транзакций.

### Карта

Карта связана:

```text
Клиент → Карта → Счёт
```

Карта не является владельцем денежных средств — владельцем денежных средств является счёт.

### Платёж и транзакция

В модели они разделены:

```text
Payment
   ↓
Transaction
```

Платёж представляет распоряжение/процесс перевода, а транзакция — факт финансового отражения операции.

Это позволяет избежать смешения бизнес-процесса платежа и финансового факта.
