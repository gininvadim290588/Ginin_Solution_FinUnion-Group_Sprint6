# Образ целевого результата (через 12 месяцев)

| Вопрос | Что описать |
|---|---|
| Какие системы остаются | **Target Core Banking** (единая платформа счетов/договоров, выросшая из FU Core), **Target Card Platform** (из FU Cards), **Target Lending Platform** (из FU Loans), **Payment Hub**, **Target Case Platform** (обращения клиентов), **MDM** (Customer Hub + Reference Data), **Integration Layer** (API Gateway/ESB + CDC-коннекторы), **Kafka**, **DWH**, **Data Lakehouse** (Iceberg + Trino), **BI**, **Antifraud/Graph DB**, **Поисковый движок**, **Объектное хранилище**, **Airflow**, **DataHub** |
| Какие системы выводятся из эксплуатации | **RB CRM** (данные и функции поглощены MDM + Target Core), **RB Core** (портфель мигрирован в Target Core Banking), **RB Cards** (портфель — в Target Card Platform), **RB Loans** (портфель — в Target Lending Platform), **RB DWH** (заменён единым DWH), **RB BI** (заменён единым BI), **Point-to-point интеграции RetailBank** (заменены Integration Layer + Kafka/CDC) |
| Какие данные мигрируются | Клиентские профили RB → MDM (после матчинга с FU); действующие и закрытые счета/договоры RB → Target Core Banking (действующие) и объектное хранилище (закрытые/архивные); карточный портфель RB → Target Card Platform; кредитный портфель RB → Target Lending Platform; историческая транзакционная и карточная история RB → Data Lakehouse; продуктовые и тарифные справочники, справочник отделений RB → MDM Reference Data; регуляторная и управленческая отчётность RB DWH → единый DWH (историзированные витрины) |
| Какие потоки переключаются | RB CRM → RB Core заменяется на CRM/Core → MDM → Target Core (через ESB/CDC); point-to-point потоки RB заменяются на публикацию в Kafka и CDC-коннекторы; RB DWH → RB BI заменяется на DWH → BI (единый); две отдельные регуляторные выгрузки (FU DWH, RB DWH → Регулятор) заменяются одной выгрузкой из единого DWH; отчётность по обращениям переключается с двух Case-систем на единую Case Platform → поисковый движок |
| Критерии подтверждения завершения перехода | 100% клиентов имеют единый golden client_id в MDM без открытых конфликтов матчинга; все системы RetailBank, перечисленные к выводу, официально декомиссированы (нет активных потоков и обращений к ним); все потоки данных работают через Integration Layer/Kafka/CDC, ни одной point-to-point интеграции не осталось; DWH и Data Lakehouse — единственные источники для BI и регуляторной отчётности; DataHub покрывает lineage 100% продуктивных источников; параллельный прогон (см. `cutover-plan.md`) завершён без критических расхождений минимум 2 отчётных цикла подряд |

## Что не меняется намеренно

Не все элементы As-Is требуют замены: справочник БИК/внешние реестры (ФНС, ПФР, ЦБ) остаются внешними
источниками валидации, как и в промежуточном состоянии — они не входят в контур миграции банка. Регулятор
как внешний потребитель отчётности также не меняется — меняется только то, что он получает данные из
одного DWH вместо двух.
